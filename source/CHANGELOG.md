# 云鲲更新记录

## v1.1.2-offline（相对 v1.1.1-offline）

本版汇总此前未发布修复，完整说明与已知限制见 [1.1.2 更新说明](docs/RELEASE_1.1.2.md)。客户现场和未列明场景不能视为已验收。

- macOS Intel/Apple Silicon 标准离线安装接入与Linux共用的一键更新事务：整包校验、依赖预检、停服停库、数据/密钥备份、迁移探测、启动检查与失败回滚；补齐macOS启动文件白名单，拒绝错误平台/架构的更新作业。
- Unix启动/停止及更新助手统一验证进程身份；macOS不再依赖命令行字符串前缀识别进程。新增原生升级/回滚验收脚本与只读CI工作流，原生验收结果仍待运行，不将交叉编译等同于实机通过。旧macOS版本首次获得此能力仍需单独迁移，不会因发布新包自动补齐旧程序。
- 报告与漏洞导出显示实际 HTTP 状态、接口路径及质量阻断原因；429 按 Retry-After 等待后允许手动重试，缺省本页等待30秒，阻止重复提交，不自动重放。任务报告切换时取消旧请求，失败响应不会下载为报告。本项改善诊断与恢复操作，不代表已定位客户环境429的来源。
- 组合回归补修：仅改池名称等元数据不再重加密凭据或撤销正常请求；手动固定及重新分配排除冷却、验证失败、证据过期和临近到期节点。
- 凭据恢复遇到并发任务操作立即拒绝并提示重试，避免反向锁等待；旧凭据或旧冷却快照的成功回调不能清除新故障。不完整 HTTP 响应不再记作运行成功。
- 新任务手动固定未选节点时禁止提交；切换池清除旧节点，忽略过期异步节点列表；自动模式仍默认轮询。
- 任务代理默认按请求轮询同池可用节点，固定节点须手动设置；CONNECT 按新连接选点，在途请求的授权检查不消耗轮询次数，也不因其他请求换节点而取消。
- 明确的代理连接故障进入持久化 60 秒冷却，安全的无正文 GET/HEAD 及未建立的 CONNECT 最多尝试 3 个出口；固定模式不切换，目标 HTTP 错误不判作代理故障，全部不可用不直连。节点页可见冷却状态。
- 不可解密池新增显式凭据恢复入口：暂停关联任务后重新填写整组认证，或对固定地址池确认无认证；保留节点/绑定和旧密文备份，旧验证失效，重新验证启用后才允许出网。
- 兼容提醒：旧版未记录节点是自动分配还是用户指定，升级后的历史绑定默认轮询；需要保持固定出口的任务应暂停后手动重新固定。发布不等于已部署客户。
- Worker、主 Agent、规划 Agent 与会话 Agent 新增受管 `cleanup_task_cache`：临时前端脚本放在各自 `cache/`，预览后可选择删除；拒绝目录穿越、链接和预览后变化的文件，不清理已有证据或旧任务根目录。
- 审核详情记录模型裁决耗时（不含人工等待），便于区分模型服务延迟与待审批阻塞；通用模型审核仍受所选供应商响应速度影响，本地未以放宽拦截规则换取提速。
- 一键更新的校验清单和完整包优先通过 GitHub 资产 API 获取，发布附件地址作为受信任回退；TLS 连接失败有受控重试和清晰的进度提示。
- 完整包下载中断时在本次更新内使用校验过的 `Content-Range` 续传；不接受不匹配的分段、无效大小或 SHA-256 校验失败的包。
- 系统标准 `HTTPS_PROXY`/`NO_PROXY` 可用于更新；显式配置的代理优先，错误的代理配置不再悄悄直连。
- 下载或校验失败清理本次临时工作目录，不停服务、不修改旧数据。备份时同步计算源哈希，仍独立校验目标哈希，减少重复磁盘读取。
- `v1.1.1-offline` 旧程序不包含这些下载改进，更新到本版后才能生效；首次下载仍受旧版下载链路和客户网络影响。

## v1.1.1-offline（相对 v1.1.0-offline）

本版整理并发布最近完成的三项修复，保留 Agent 底座、模型选择、任务授权和已有数据迁移边界不变。

- Linux 标准离线安装支持受管一键更新：下载校验、停服停库、完整备份、迁移探测、启动检查和失败回滚。
- Agent 并发设置实时作用于已有任务；扩容补 Worker，缩容只退休超额 Worker，避免重建任务和重复退休。
- 固定代理池支持 TXT/CSV 导入、CSV 导出、去重、大小/数量限制和后台自动验证；验证失败不启用，页面关闭或服务重启后可继续。
- 修复代理候选恢复授权后的验证状态判断，未重新验证的候选不会被错误放行。
- 增加并发、代理导入、更新事务、更新回滚及前端流程回归测试。

验证边界：Windows 升级和回滚、全量 Go 测试、`go vet`、前端构建及 Linux 双架构交叉构建已通过；Linux 原生 PostgreSQL/进程升级尚未在真实 Linux 主机验收。详见 [1.1.1 更新说明](docs/RELEASE_1.1.1.md)。

  服务重启后过期领取记录可继续处理；重复节点保留来源、证据和启用状态。
- 修复恢复代理候选授权后仍提示越权的状态判断；仍须重新验证后才能入池。
- 增补导入鉴权、CSV 多行/BOM、去重及恢复测试，扩缩容与更新事务故障测试。
  此段不代表此前全部未提交功能均已验收；提交、发布和部署须分别记录。

从本仓库 [v1.0.3 Release](https://github.com/Haryy985/yunkun-console-preview/releases/tag/v1.0.3-offline)
下载 `yunkun-v1.0.3-offline-windows-x64.zip` 和 `SHA256SUMS.txt`。
GitHub 自动生成的 Source code ZIP 是源码快照，不是离线安装包。

- 压缩包：70,813,354 字节，约 70.8 MB。
- SHA-256：`82e00cc162c3c4a23f9b05621a14d29102f107cd38b4ff77c78affb88a8768fb`
- 解压后双击 `setup-and-start-offline.bat`，等待就绪后访问 `http://127.0.0.1:5173/`。
- 管理员账号为 `yunkun`，首次自行设置密码，没有统一默认密码。

包内含编译后的控制台、当前内嵌页面、PostgreSQL 18.4 和工作流资料。

## 修复与优化

| 模块 | 变化 |
| --- | --- |
| Agent 上下文 | 移除二开引入的未知模型固定 64K 本地请求拦截，保留原有可配置压缩。供应商真实容量仍需正确配置，不能据此保证长任务永不超窗。 |
| 模型工具回合 | 保留 SDK 捕获的 reasoning 数据。对缺少历史推理且没有显式 thinking 配置的特定拒绝，仅在输出未提交时尝试关闭 thinking；不编造推理内容，不全局关闭思考。 |
| 错误处理 | 区分上下文过长、额度耗尽、暂态传输及明确的订阅不可用，不把普通鉴权失败当额度耗尽，不无限重试。 |
| FOFA / Quake 发现 | 每次 100–1000 条，持久保存下一页位置；结果和游标事务提交。失败重试当前页，业务错误不误判为结果取尽；条件变化后重置游标。重复结果仍去重，不保证每次都产生新 IP。 |
| 代理验证 | 全服务最多同时验证 10 个，每个实际验证限时 3 秒；排队时间不计入连接期限，取消与配置变化受检查。 |
| 跨页全选 | 选择当前筛选下全部可操作候选，分批提交；已入池节点在节点页管理。 |
| Finding 质量 | 要求验证过程和本任务真实成功工具步骤或核实流量引用，证据不足保留为线索，避免只凭状态码、版本或扫描器告警确认漏洞。 |
| 报告导出 | Markdown 交付视图清理旧 curl 复现命令及其续行；动态代码围栏避免证据内容破坏 Markdown。保密 HTTP 原文经权限检查和审计输出。 |
| 初始化认证 | 读取失败默认拒绝，并发首次设置不能覆盖已有密码；密码版本使旧会话失效，损坏签名密钥不静默重建。 |
| 文件与请求边界 | 加固工作空间路径、上传与 Skills ZIP 安全替换；数据库标识符正确引用；跨域仅接受明确配置的可信 Origin。 |
| 云鲲界面 | 保留分组导航、模型及设置页排版，同时合并画像、质量审核、报告与版本入口。 |
| 离线迁移 | 增补代理凭据加密密钥迁移，完整备份后校验哈希；保留自定义 Skills，同名新版默认资料另留供对比。 |

## 更新提醒与升级

1.0.2 已具备基础版本检查，本版补齐它与当前导航、设置页的连接。
管理员可查看新版、发布说明及下载入口。需要能访问 GitHub；断网不会收到在线提醒。
目前不自动替换运行中的程序，早于检查功能的旧安装需要先手动升级一次。

不要覆盖正在使用的旧目录。暂停任务并停止旧服务，将新包解压到全新目录，
按[离线更新手册](OFFLINE_UPDATE.md)运行 `upgrade-offline.ps1`。
脚本先备份旧安装，再迁移私有数据、JWT 密钥、代理加密密钥和用户 Skills，并校验哈希。
旧目录与备份均保留。外部数据库或自定义绝对路径须单独确认。

## 当前边界

没有把全部 Python 脚本改写成 Go。主动爬取须先接通受管出口及抓包，再作为新工具开放；
专项资料不等于全部脚本已成为运行能力。原生 Agent 仍继承启动账号权限，
局部证据关联也不等于跨任务完整因果图。

本版未用真实模型、付费情报平台和真实授权目标跑完整任务。
自动测试不等于无漏洞或公网部署验收；独立报告交付角色和运行中自动升级尚未提供。
既有许可证、来源和仓库使用条款保持有效。
