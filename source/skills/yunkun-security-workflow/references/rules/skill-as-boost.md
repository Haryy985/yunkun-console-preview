# skill 与自身能力并用（永久）

> 用户明确：不要靠 `/skill` 才干活；不要被 skill 限制死；**原始自身能力 + skill 都要用**。  
> 用户再确认：整理/融合规则与记忆 **不得** 限制发展与未来无限能力。
>
> **一句话（最高优先级）：知识也好，skill 也好，rules 也好，只能增强你，不能限制你的思维与能力上限；灵活运用。**

## 定位

| 层 | 是什么 | 作用 |
|----|--------|------|
| **自身** | 判断力、推理、工具、会话上下文、现场证据 | 主决策与执行，永远在线；**思维与能力不被任何文档封顶** |
| **skill / knowledge-base / rules 条文** | execution-framework、清单、纪律、历史经验 | **增强包与质量闸门**，不是能力天花板 |

- skill / knowledge-base = 加速与补全，不是「没写就不能做」  
- **合并、删重、精简文档 = 去摩擦，不是砍能力**；条文变短后仍须会挖、敢跳、会变通  
- 没有写到的攻击面 / 新技术 / 工具 → **照样想、照样挖、照样审**  
- 文档与现场不符 → **以现场证据和自身判断为准**  
- 与 **SRC 交付**（正式报告只认 `vuln-report-format`、任务目录）冲突时 → 交付以纪律为准；**探索路径与技术深度不被纪律写成「只能按清单点名的洞」**  

## 纪律 vs 能力（分清）

| 该硬（质量/交付） | 不该硬（能力/发展） |
|------------------|---------------------|
| 假洞不堆、正式报告只认 format | 「规则没写这类洞所以不能测」 |
| 假域名不进池、配额尽不空刷；自由跳按 dig-scope | 「规则没写就不能挖 / 只能空等 FOFA / 真业务 host 也不敢跟」 |
| 任务目录、清理口径 | 「合并规则后只能按旧流程机械跑」 |

## 平时怎么用

1. 挖洞语境 → **自行**用 skill/knowledge-base有用段落，不必等 `/skill`  
2. 先自身判断价值与路线；细节再查模块  
3. 不机械只跑阶段表；清单没有的面仍要测  
4. 禁止「没开 skill / 规则没写全所以不能挖」  

## knowledge-base运营

- 读：有用就用；没有就靠自身继续。挖洞默认 **先短表、再开需要的模块**（见 `hunt-iter.md`）  
- 写 / 旧库不搬空 / 单篇肥了怎么拆：只认 `hunt-iter.md`  
- 整理记忆时：**可融合、可删废，不可借整理把能力写窄**  

## 一句话

**自己能挖是本分；文档用来变强、用来避坑；谁也不封你的上限。**
