# 过审报告模板（从语料实证提炼）

## 模板 A：逻辑/越权/信息泄露（黑盒，主流 80%）

```
【标题】XX公司XX系统存在XX漏洞（一句话：谁的站 + 做成了啥）

漏洞简述：
（第一人称大白话 2-3 句：我在哪个功能、通过什么操作、做成了什么）
例：在忘记密码处输入已注册手机号和未注册手机号返回不同响应，
同时返回的 pid/selectid 可在另一个接口中利用，造成账号信息泄露。

漏洞证明：
1.（完整 URL + 操作描述 + 截图/回包关键行）
2.（利用 pid 的第二个请求 + 响应差异）
每步：一个可复制整包（Burp 原始包格式，token 实值嵌入）或截图

危害说明：
（最终真实伤害，举实值例：姓名/手机号/证件或内部标题；
能批量就写"可批量"；禁止"不限于/等敏感信息"）

修复方案：
（1-2 句针对性建议）
```

## 模板 B：硬编码凭据（App/JS 密钥泄露，语料范式=同程 app 百度 key）

```
1. 漏洞简述：XX app 反编译获得 XX 平台 API key，可任意调用付费服务
2. 复现步骤：
   a. app 下载链接（完整 URL）
   b. 反编译 → Manifest 里的 meta-data 实值（APP_ID/API_KEY/SECRET_KEY 原文贴出）
   c. 用官方 oauth 接口换 access_token（完整请求 URL 含实参）
   d. 用 token 调用付费接口实测成功（在线工具链接 + 成功响应）
3. 危害：接管付费服务、按次计费损失（过认钥闸：真值实锤 + 带出身份/列表）
4. 修复：全部更换密钥 + 加固混淆
```

## 模板 C：白盒 0day（组件/CMS 漏洞，语料范式=UsualToolCMS）

```
1. 环境：版本精确到 Release + 官网下载链接
2. 漏洞分析：文件路径 + 行号 + 未过滤变量 + 数据流（从 GET 参数到 SQL）
3. payload：完整可复制 URL
4. 利用：时间盲注给完整 Python 脚本（requests + 延时判定）
5. 爆库 payload：information_schema 语句
```

## 模板 D：弱口令（EduSRC 高频，语料范式=云南师大）

```
标题：XX大学XX系统存在弱口令漏洞
正文：系统 URL + 账号（system_admin）+ 密码（默认/弱口令实值）
证明：登录成功截图 + 登录后可见的敏感功能面
（必须闭环到"进了系统看到什么"，单独爆破成功不写）
```

## 定级参照（语料定级词频 + 499 规则融合）

| 级别 | 判定线（从严） |
|------|----------------|
| 严重 | 命令真跑起来 / 进了别人的号或改掉密绑 / 钱真转走或状态真变 |
| 高危 | 对得上人（手机/证件/卡）/ 云密钥·token·连接串过认钥闸 / 注入出对方主体数据 / 他人未公开业务正文 |
| 中危 | 有权限扩大或业务敏感，上面两条一条不中 |
| 不写 | 半条链 / 无密钥壳 / 低危信息级 / 拿不准 |

## 提交前五问（过闸自查）

1. 打通的包带没带会话？（匿名闸）
2. 密钥是否生产实锤 + 带出身份/列表？（认钥闸）
3. 伤害清单里每条都真验证过或边界写清了吗？
4. PoC 复制粘贴就能跑吗？（无占位符/省略号，Header 精确）
5. 这个洞在本任务里重复交过吗？（同类型同 URL 换 id = 同一条）
