# Lane · Authenticated Workflow Assurance

## 适用信号

- 已登录后的创建、查询、修改、删除、审批、成员管理、订单、邀请、重置、导出或配置变更。
- 同一业务对象跨页面、REST、GraphQL、WebSocket 或 SSE 流转。
- 权限依赖用户、角色、租户、组织、所属关系或对象状态。

## 先建最小矩阵

每个高价值模块先记录，而不是直接按接口数量发包：

| 维度 | 最小对照 |
|---|---|
| 身份 | 当前测试身份；有第二个已授权测试身份时加入角色或租户对照 |
| 对象 | 自有对象、另一个可区分的测试对象、不存在对象 |
| 状态 | 当前正常状态与一个相邻合法状态，如草稿/已提交或启用/停用 |
| 传输 | 由真实运行时动作产生的页面请求、REST、GraphQL、WebSocket 或 SSE 消息 |

没有第二身份、第二对象或相邻状态时，保留该维度的 `partial` 或 `blocked`；不得把只验证当前用户正常功能写成“业务授权已覆盖”。

## 最小验证链

1. 用一个正常动作建立 identity -> object -> state -> response 的 baseline。
2. 选择一个边界和一个变量：身份、对象键、状态、字段级权限或传输面之一。
3. 使用负对照确认差异不是缓存、前端路由、错误处理或对象不存在造成的。
4. 对写操作保存 before/after 证据，并在创建测试状态时登记 cleanup。
5. 只在结果可复现且真实归属、状态或敏感字段越界时提升 finding 层级。

## 高价值分支

- `object-lifecycle-authz`: 同一对象在详情、编辑、删除、导出、附件和任务结果中的归属是否一致。
- `state-transition-authz`: 后端是否在每一步重新验证角色、对象和前置状态。
- `field-scope-diff`: UI 隐藏、列表脱敏与 API 实际返回字段是否一致。
- `stale-session-state`: 权限、成员关系或对象状态变化后，现有会话和订阅是否仍被错误接受。
- `bulk-export-scope`: 批量、导出、筛选、下载令牌和异步结果是否沿用同一授权范围。

## 证据与停止

- BOLA/IDOR 仍必须完成 own / other / nonexistent 三联验证，并只改变对象标识。
- 只有一个身份时优先完成对象和状态对照；不猜测未取得的角色能力。
- 已证明一个最小边界后，转向下一模块；不要为扩大数据量继续枚举对象、用户或端点。
- 协议细节以 `runtime-protocol-assurance.md` 为准，异步链以 `async-integration-assurance.md` 为准。
