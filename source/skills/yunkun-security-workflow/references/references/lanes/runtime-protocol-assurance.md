# Lane · Runtime Protocol Assurance

## 适用信号

- 页面或小程序的真实动作发出 `fetch/XHR`、REST、GraphQL、WebSocket、SSE 或订阅消息。
- 前端代码、浏览器网络面板或运行时 hook 显示 API 路径、订阅、重连、事件流或隐含状态。

## 运行时优先

静态 JS、schema 和路径字典只产生候选。先用一个正常用户动作记录：触发页面状态、请求或握手、认证工件是否携带、对象/租户字段、响应或事件、UI/持久化结果。只有已观察到的真实协议消息才进入主动验证。

## 最小验证链

1. 捕获正常 baseline：一个动作、一条请求或订阅、一条结果或事件。
2. 选择单一变量：对象键、订阅主题、状态、角色、会话更新或重连时机。
3. 记录负对照，排除客户端缓存、历史事件、前端过滤或消息顺序导致的假差异。
4. 对 GraphQL、WebSocket、SSE 分别验证建立、授权、结果和断开/重连后的边界；不把握手成功等同于可读取受保护内容。
5. 发现新 API host 时，只有它是运行时直接依赖才纳入当前链，并保留来源请求或脚本证据。

## 高价值分支

- `subscription-authz-diff`: 订阅主题、对象范围和租户边界是否在服务端验证。
- `reconnect-session-boundary`: 角色、对象或会话变化后，重连和旧订阅是否仍被错误接受。
- `protocol-field-scope`: 客户端隐藏字段与服务端实际返回的字段范围是否一致。
- `transport-consistency`: 同一业务动作在 HTTP、GraphQL 和实时通道上的授权与状态判断是否一致。

## 证据与停止

- 每个结论至少保留正常帧、单变量帧和负对照，以及对应的可见业务结果。
- 不枚举主题、频道、operation name 或历史事件来填覆盖率；没有运行时动作支撑的候选保持 observation。
