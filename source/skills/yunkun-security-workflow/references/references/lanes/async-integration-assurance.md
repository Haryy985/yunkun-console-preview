# Lane · Async And Integration Assurance

## 适用信号

- 审批、导入、导出、批处理、报告生成、通知、队列、worker、重试、取消、定时任务。
- webhook、回调、第三方同步、支付/消息/存储集成、文件解析或下载令牌。
- 页面动作返回任务 ID、进度、状态轮询、结果链接或稍后通知。

## 先画一条真实链

先用一个自有的正常动作，把以下节点按真实顺序连起来：

`actor -> 请求/持久化对象 -> job/event -> worker/callback -> 状态/结果 -> 下载或通知`

对每个节点记录谁发起、哪个身份被携带、对象和结果归谁、可否重试/撤销、何时失效。不要因为看到队列名称、回调字段或内部域名就直接枚举下游拓扑。

## 最小验证链

1. 捕获一次正常且可清理的自有任务或集成请求。
2. 保存创建、状态、结果三个阶段的原始证据；异步链必须有可关联的对象或任务标识。
3. 一次只验证一个边界：任务归属、结果归属、状态转换、取消/重试权限、回调来源或下载令牌之一。
4. 以自有对象、另一测试对象和不存在对象做必要对照；若缺失第二身份或对象，明确标记覆盖缺口。
5. 完成最小影响证明后停止横向枚举，清理测试任务、文件、通知或配置。

## 高价值分支

- `job-result-ownership`: 创建者、当前操作者和结果读取者是否被一致绑定。
- `retry-cancel-boundary`: 重试、取消、恢复、失败重放是否重新检查对象和角色。
- `callback-trust-boundary`: 回调身份、事件关联和最终状态是否被服务端验证，而不是仅靠客户端字段。
- `export-download-lifecycle`: 导出任务、下载令牌、缓存副本和到期后的归属是否一致。
- `idempotency-state-gap`: 正常重复提交、网络重试或撤销后的状态机是否出现可复现的非预期状态。

## 证据与停止

- `success=true`、任务创建成功或单一进度页不是 finding；必须证明错误的身份、对象、状态或信任边界。
- 不用并发、批量或大范围回放代替最小生命周期证明。只有现场明确出现竞态信号时才按需读取 `references/playbooks/race-conditions.md`。
- 对第三方服务仅验证当前应用直接产生的请求和回调关系；不要扩展为资产测绘或服务枚举。
