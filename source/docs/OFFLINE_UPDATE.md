# 离线安装与升级

Windows 部分适用于包含 bin/yunkun.exe 和 runtime/pgsql-18.4 的 Windows x64 完整包。
先核对发布页 SHA-256；GitHub 自动生成的源码 ZIP 不能代替离线包。

## 新安装

1. 解压到当前用户可写的独立短路径。包内包含 `runtime/vc_redist.x64.exe`；如果目标机缺少 VC++ x64 运行库，启动器会请求管理员权限自动安装。
2. 双击 setup-and-start-offline.bat，等待健康检查成功。
3. 浏览器打开 http://127.0.0.1:5173，首次为 yunkun 自行设置密码。
4. 配置自己的模型、知识库权限和工具。原始数据初始为空。

默认应用监听本机 5173，数据库监听本机 5433。端口被占用会停止并提示，
不会终止未知进程。可用 PowerShell 指定数据库端口：

```powershell
.\setup-and-start-offline.ps1 -DatabasePort 55433 -NoBrowser
```

本地数据在 .yunkun-local；JWT 和代理加密密钥在 bin 下。均为私有数据，
不能上传或转发。安装无网络依赖不等于配置的云端模型可在断网时运行。

## 公网访问

默认启动只监听本机 `127.0.0.1:5173`。确认云安全组和 Windows 防火墙已放行 TCP 5173 后，使用：

```powershell
.\setup-and-start-offline.ps1 -Public -NoBrowser
```

`-Public` 会监听 `0.0.0.0:5173`。不要在未配置认证、访问控制和 TLS 的情况下直接暴露到公网。

## 从 1.0.6 升级到 1.1.0

1.0.6 已发布客户端没有应用内安装入口，首次升级仍按下面步骤执行。
安装包含一键更新的新版本后，后续升级可在页面完成。

暂停任务，在旧目录运行 stop-offline.bat，确认应用和私有数据库停止。
把新包解压到另一个全新目录。准备与新旧目录互不包含且尚不存在的备份目录。
在新目录运行：

```powershell
.\upgrade-offline.ps1 -OldDirectory 'F:\yunkun-old' -BackupDirectory 'F:\backups\yunkun-before-110'
```

脚本先备份并校验整个旧安装，再迁移 .yunkun-local、bin/jwt.key、
bin/proxy-pool.key 和用户 Skills，核对哈希。旧安装及备份不删除。
同名 Skills 以用户旧文件为准；新版默认资料另留在
.yunkun-local/upgrade-bundled-skills，可逐项对比后决定采用。
外部数据库、外部工作空间及自定义绝对路径须另行备份确认。

迁移成功后双击新目录启动器。检查版本、登录、历史任务、知识库、
代理凭据和报告，不能只以页面能打开判断全部功能通过。
应用启动会执行 schema 迁移；本版新增画像、质量状态及代理游标等字段。

1.1.0 收紧普通账号权限：operator 和 viewer 暂不能查看/启动任务、读取发现、
代理池或调用执行接口，管理员不受影响。现有任务及数据不会删除。待按用户的
任务归属与宿主机执行隔离完成后，才能重新开放这些角色的任务权限。
登录限流按连接来源和账号统计，反向代理后的多名用户可能共享来源配额；
部署时保留访问日志，不直接信任客户端发送的 X-Forwarded-For。
公网部署应先在本机完成管理员首次设置，并在反向代理阻断 /api/auth/init，
同时提供 TLS、访问限制和独立低权限运行账号。限流不是公网安全验收。

## 回滚和在线提醒

### 一键更新

Windows x64 标准离线安装需通过包内启动器启动。
管理员进入“系统设置 → 版本与更新”，阅读发布说明，点击“一键更新”，
确认“备份并更新”。运行或排队中的任务须先暂停，Agent 对话和复测须先结束。
更新按钮不会打开 GitHub；“打开发布页”仍作为独立的手动下载入口。

更新器固定读取云鲲 GitHub 发布源，校验 SHA-256、路径、包大小、完整运行时
及程序版本。下载和校验失败不会停止旧服务。检查通过后进入维护状态，
停止应用与私有 PostgreSQL，再校验备份、替换程序和运行时、重启。
首先进行不启动 Agent 的数据库迁移与认证检查，再启动完整服务。

数据库、配置、JWT 密钥、代理加密密钥和用户 Skills 会保留。
同名 Skills 以客户旧文件为准，新版默认文件放在
`.yunkun-local/upgrade-bundled-skills`，避免覆盖用户修改。
完整备份及失败后的文件副本保留在 `.yunkun-local/updates/<本次更新>/`，
页面会显示备份路径。备份包含客户私有信息，不得随软件包分发。
失败时恢复的是更新前程序与数据库的一致快照，不只替换旧 EXE。

更新状态持久保存在 `.yunkun-local/update-state.json`，刷新页面后可继续查看。
服务停止期间页面会显示重新连接，成功后点击“重新载入控制台”。
电源中断、磁盘损坏或自动恢复失败不能保证自动自愈；启动器会拒绝覆盖或
重新初始化未完成的安装。保留备份和更新日志后进行恢复。
外部数据库、自定义配置目录不开放应用内换装；Linux 开发版支持范围与验收边界见下节。

### Linux 开发版更新（2026-10-24，待原生验收）

Linux amd64/arm64 的标准离线包接入相同的页面入口。必须以普通用户通过
`start.sh` 或 `bin/yunkun-offline` 启动，使用内置 PostgreSQL 18、
标准 `.yunkun-local` 配置和数据目录。macOS 当前仍使用手动升级。
更早发布且未包含本功能的 Linux 客户端须先手动升级一次；发布新版不会
使旧程序自动获得更新代码。本节描述未发布开发改动，尚不能替代 Linux 实机验收。

助手与应用使用独立进程会话，等旧启动器释放锁、确认数据库停止后再备份。
先检查磁盘容量、完整 ZIP 校验、候选程序/启动器版本和依赖；不足时保留旧服务。
升级失败恢复程序和数据库的同一份快照，保留失败副本；停库无法确认时拒绝复制。
标准启动器在 `waiting/backing_up/installing/starting/rolling_back/recovery_required`
状态拒绝普通重复启动，由受管更新助手完成恢复。不要删除更新状态文件来强行启动。

原生验收脚本为 `tests/offline-oneclick-unix-smoke.py`，需要两份无数据、
可抛弃的 Linux 安装目录，使用隔离端口和合成任务/知识库/代理凭据，
验证成功升级、启动失败回滚、登录/旧会话、历史数据、密钥及用户 Skills。
手动 CI 为 `.github/workflows/linux-update-regression.yml`，只在人工触发时运行。
本机 Windows 验证只覆盖事务逻辑、文件快照和交叉编译，不能据此声明 Linux 原生升级通过。

### 手动恢复

失败时保存日志，不要删除或重新初始化数据库。停止新安装，保留失败副本，
使用升级前完整备份在独立目录恢复。不要把已迁移数据库直接交给旧程序。
回滚可能丢失备份以后的变更，应先留档。

管理员登录后顶部提示和“系统设置 → 版本与更新”检查固定云鲲发布源，
显示版本与发布说明，支持打开下载页。断网不影响本地运行，但无法在线查新。
早于一键更新功能的旧客户需手动升级一次；发布新版不能改变旧客户端已有代码。
