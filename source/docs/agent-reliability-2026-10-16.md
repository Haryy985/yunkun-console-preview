# Agent 稳定性修复记录

日期：2026-10-16
维护者：Rowan / 云鲲安全

## 修复内容

### 旁路会话检查点

`side_question_sessions` 只允许“对话归属”或“任务归属”二选一。旧逻辑在 `conv-*` 会话同时继承任务运行信息时，把 `conversation_id`、`task_id` 和 `exploration_id` 一起写入，触发 PostgreSQL `SQLSTATE 23514`。失败快照会被后台刷新器反复重试，造成日志风暴。

现在对话会话优先使用 `conversation_id`，任务会话才使用 `task_id + exploration_id`，两类字段不会混用。无效归属不会安装旁路检查点捕获器。

### Agent 上下文预算

请求预算估算会同时计算系统提示、工具定义、历史消息和嵌套工具结果。旧逻辑在请求已经接近本地 64K 上限、但仍有少量输出空间时，仍按“至少 4096 输出 Token”拒绝请求，导致 Planner 在发出任何工具调用前直接进入 `prompt_too_long`。

现在 `MaxTokens` 被视为上限，不再是必须预留的固定值。未配置时保持原版 SDK 适配器行为：OpenAI 格式普通请求不发送输出上限，Anthropic 格式默认 8192；只有本地估算接近容量时才缩小上限。安全预留按窗口大小缩放，避免在未知 64K 窗口中额外吞掉 5% 的可用空间；边界请求最低保留 1024 Token 输出。对未知窗口允许最多 16K 的有限软探测，并限制为 1024 Token 输出；明显超出软探测范围的请求仍会被拒绝并交给上下文压缩或错误处理。软探测不能代替真实模型容量配置。

## 验证

- 旁路会话父级归属互斥测试通过。
- 接近上下文上限时自动缩小输出预算的回归测试通过。
- 未设置输出上限时保持 SDK 适配器默认行为的回归测试通过；HTTP 请求体断言覆盖 OpenAI、Anthropic，以及小窗口下 Anthropic 默认输出必须缩减。
- 安装源码的 Agent 与服务端聚焦测试通过；离线源码包和安装源码的所有 Go 包编译检查通过。
- 未连接用户数据库，要求 PostgreSQL 的集成测试未执行；尚未使用真实任务和模型验证 Planner 到 Worker 的全链路。v1.0.1-offline 交付包已重新编译，但已有安装及其运行进程不会自动更新，需按 [离线更新手册](OFFLINE_UPDATE.md) 操作。

## 影响范围

本次修改只涉及旁路检查点归属和模型请求预算，不改变工具集合、RAG 数据、代理池配置、任务数据或模型密钥。
