# 云鲲代理池 V2 开发蓝图

状态：实施中（2026-10-21 开发树）。未发布，未在客户机完成同条件对照。

## 目标与边界

把“搜索到代理地址”“能连接代理”“能通过代理访问验证站”“能访问授权目标”“任务实际使用该出口”分成五个独立结论。解决大量候选只有极少数可用时无法归因、超时被反复验证、协议猜错以及任务页面容易误读为全流量强制代理的问题。提高诊断准确率优先于提高表面成功率。

保留固定节点、小象代理、通用 JSON API、FOFA、Quake 与手动节点，保留现有任务和凭据。发现查询可以先保存而不填写授权范围或验证地址；只有明确授权的来源/节点才允许主动探测和入生产池。搜索平台的结果不是对目标或第三方代理进行主动验证的授权。默认只连接本机服务，不改现有数据库或运行进程，实施与验收使用隔离库。

本期不宣称 Agent 全流量强制代理：目前受管 HTTP/WebFetch 走任务网关；Bash 仅使用环境变量，交互 Shell、浏览器/MCP、自定义网络工具、资产补全、WebSearch、模型及情报供应商请求尚无统一出口约束。不能以代理池验证通过推断它们已走代理。不做静默直连回退或全局操作系统代理修改。

## 当前基线与已知缺口

| 环节 | 现状 | 改造重点 |
| --- | --- | --- |
| 来源 | FOFA 用 `qbase64`、`size/page`；Quake 用 `query/size/start`；查询和游标保存在数据库 | 保留用户语句、平台响应分页事实、去重及错误分类；防止重复页或错误推进游标 |
| 协议 | FOFA 只把包含 socks 的结果识别为 SOCKS5，否则 HTTP；Quake 只识别 socks5，其余 HTTP | 明确 HTTP/HTTPS/SOCKS5/未知；未知仅待人工确认，不猜测、不入池 |
| 候选验证 | 自动与批量验证 10 个并发、单条 3 秒，IP 回显地址；超时回到 pending | 分阶段记录失败、有限复核、停止条件；区分未验证和已尝试超时 |
| 入池 | 对目标池凭据或验证地址改变会重新验证；验证通过才可入池 | 复验沿用同一协议和可比目标，保存证据版本与有效期；默认待启用 |
| 节点 | 最近错误、成功失败次数、延迟、到期状态；已有分页与逐节点开关 | 区分最近一次与时间窗表现，展示各阶段结果；过期/失效不继续选路 |
| 出口 | 任务绑定和网关路由有审计事件；`enforced=false`、覆盖 `managed_http_tools_only` | 按工具标明覆盖，关联任务/节点/请求结果/抓包 ID；无法保证的工具禁止误标 |

## 实施阶段

### 一、建立可追溯的发现批次和诊断统计

新增发现批次记录：来源 ID、时间、查询版本摘要、平台页/偏移、请求条数、返回条数、新增/重复/过滤/协议未知/授权不匹配数量、平台状态及结束状态。候选关联批次；另存每次验证尝试，记录阶段、固定错误码、模式、目标的脱敏 origin、耗时、出口 IP、HTTP 状态与时间。不存原始 Cookie、Token、验证 URL 查询串或响应正文。历史候选不伪造尝试记录；迁移后统一标“历史记录/证据未知”。

统计展示两个分母：本次平台返回的记录数与本次真正开始验证的唯一候选数。页面并列显示待验证、排队、验证中、TCP 不通、协议/认证失败、目标失败、已验证、已入池、已启用；旧记录与当前批次分开。取消与排队中断不计作节点不健康。批次运行中进度和失败原因在刷新后可恢复，错误详情只用安全码和说明。

### 二、统一来源适配与分层验证

来源接口统一返回候选、原始页位、是否确定存在下一页、平台错误码；数据库在同一事务内保存候选与游标，失败不前进。遇到分页参数或额度限制时显示明确提示，保留用户的自定义查询。协议从结构化字段读取：已知 HTTP/HTTPS/SOCKS5 才进入对应握手，未识别项标“未知”并要求人工选择后重新验证。考虑对同一 host:port 的不同协议分别建候选，同时对相同来源、协议、地址去重；迁移前先核查旧唯一键及引用关系。

验证分三级，阶段和模式分别持久化：

1. 连接与协议：TCP 建连、HTTP CONNECT 或 SOCKS5 协商、认证，明确区分拒绝、重置、超时、认证和协议不匹配。
2. 出口证明：通过代理访问受控 IP 回显服务，验证 TLS 和响应，记录实测出口 IP；回显服务不可达时只说明“出口未证实”，不把代理直接判死。
3. 授权目标：仅在显式填写并核准目标范围后，以用户指定的安全验证地址测试目标连通性；目标拒绝/403/429 与代理故障分开，避免探测超出授权范围。

保持 10 条活跃验证的默认上限；3 秒作为快速尝试的可配置档位，不作为唯一生死判定。每个节点超时只允许有限次数、带退避的复核，限制每来源及全服务的排队长度和请求速率。并发只计实际网络验证，排队等待时间单列。停止、重启、来源修改时未完成项转为“待复核”，不可伪造失败；工作队列从数据库恢复，禁止无限创建 goroutine。验证服务使用受限响应体、TLS 校验、目标白名单及 URL 解析/重定向限制，防止验证地址成为 SSRF 通道。

### 三、节点健康、选路与使用证明

候选验证通过后先进入待启用池；入生产池必须复用候选协议、目标和凭据，发生变化则重新验证。节点状态为待验证、可用、异常、冷却、即将过期、停用；健康评分使用有上限的近期时间窗、延迟和新鲜度，不以累计总次数掩盖近期失败。只从启用、证据有效、未临期且符合任务协议的节点中分配；无可用节点时受管请求失败关闭，不自动直连。节点正在被任务使用时的停用/删除须二次确认并提示影响范围。

任务详情逐次显示“工具能力类别、绑定池、租约版本、节点 ID、目标 origin、网关结果、出口证明状态、抓包 ID”。仅受管请求显示“已由网关控制”；Bash 等标“环境引导/未强制”，未受管工具不能宣称已代理。若以后实现所有网络工具的强制隔离，需要单独的执行容器/沙箱网络策略设计与跨平台验收，不能靠设置 `HTTP_PROXY` 达成。

### 四、页面与运维

页面保留现有总览、来源、代理 IP、任务使用入口。总览优先放本次批次漏斗和失败原因分布；来源页显示查询、额度/分页、上次错误、批量大小；节点页按状态/协议/来源/批次筛选和分页，保留单个及跨页选择、启停与删除。点击批次可查看脱敏事件和一次复核入口。为商业/自建节点单独显示到期和余量，不与 FOFA/Quake 发现的公开候选混算。

## 风险控制与回退

- 迁移只增表/列/索引，先备份并在旧数据副本上试跑；先启用记录与展示，再切换验证器和调度器。旧记录、凭据密文、绑定、租约和启停状态不重置。
- 发现请求失败、429/额度不足、空页、重复页、重启与用户取消均不得误写“已取尽”或推进游标；分页以平台响应和供应商规则为准，针对 FOFA/Quake 分别做契约测试。
- 保留旧验证路径作为受控回退开关，回退时仅停止新验证调度，不抹去新的尝试记录。数据库迁移有向前兼容策略；不在生产库执行破坏性降级。
- 代理节点可读取经由它的通信；带认证信息的真实任务默认使用可信商业或自建池。明示来源可信级别、数据泄露风险与出口覆盖范围。
- 日志、响应和导出统一脱敏；平台密钥、代理凭据、目标 URL 查询串不进入普通 UI 或诊断包。

## 验收门槛

1. 单元/集成测试覆盖三协议、未知协议、HTTP CONNECT/SOCKS5 认证、TLS、目标响应、超时/取消、去重分页、游标事务、迁移、重启恢复、权限边界和脱敏；前端构建与桌面/移动端分页、筛选和启停交互通过。
2. 在隔离环境用可控代理与回显站证明成功/失败分类正确，走受管任务请求后核对出口 IP、网关事件及流量 ID；关闭节点时验证无直连回退，Bash/MCP 明示未强制。
3. 客户现场对照：同一台机器、同一批经授权代理、相同协议/凭据/验证地址、相同并发与超时，同 TScan 逐条对比。只汇总匿名 ID、阶段、错误码和耗时；对差异样本再诊断。不能仅用“8000 中 7 个”作为代码缺陷或优化成功的证据。
4. 将验收结果拆成已通过、待客户环境验证、已知不覆盖。只有真实出口与任务使用证据具备时才宣传对应能力；发布及替换现有 5173/5174 进程另行执行，不在蓝图阶段进行。

## 交付顺序

先完成阶段一和二的后端/测试，再做阶段四的统计与操作页面，然后接阶段三的任务选路与审计，最后执行隔离与客户现场验收。每阶段都有独立可回退的数据库迁移和验收记录；未达到门槛不进入下一阶段，也不发布离线包。
