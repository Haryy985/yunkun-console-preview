## 为什么做云鲲

安全测试并不止于“运行一次工具”。任务执行时，需要知道 Agent 正在做什么、使用了哪些工具、检索到了什么内容；得到一个可疑结果后，还需要回到原始请求和响应，判断证据是否足够、结论是否可靠。

云鲲希望把这些原本分散的环节放到同一个工作台：从对话进入任务，从执行流水查看过程，从流量与证据复核发现，最后整理为便于复现的报告。

重点不是让 AI 给出更多结论，而是让人能够看懂过程、核对依据，并对需要确认的操作保留控制权。

## 核心模块

下面介绍当前源码中的模块范围，不把模块存在等同于完整业务验收通过。

| 模块 | 关注的问题 |
| --- | --- |
| 对话与任务 | 把需求转为可管理的任务，集中查看 Agent、Worker、模板与批量操作 |
| 执行流水 | 查看任务事件、工具记录、运行状态和模型用量，遇到异常能够回看过程 |
| 知识库 | 管理文档与检索记录；Agent 提出的知识新增或修改先经人工审核 |
| 代理资源 | 管理代理来源与节点，接入 FOFA / Quake 发现入口，查看验证及出口审计记录 |
| 流量与证据 | 将请求、响应、工具结果与漏洞发现放在可复核的记录中 |
| 报告与扩展 | 以 HTTP 请求包组织复现材料，配置模型、工具、MCP 与 Skills |

### 让执行过程可以追溯

我们关心的是“这个结果来自哪里”。因此，工作台围绕任务事件、工具执行、流量与证据提供查阅入口，而不是把一段模型回答直接当作事实。

这里展示的是可审计的操作记录与公开摘要，不是模型内部隐藏的思考过程。完整的跨模块因果链仍需要真实任务逐项验收。

### 让知识更新保留人工把关

知识库可以积累方法、文档和经验，但知识条目本身不能证明某个目标存在漏洞。

Agent 提出的新增或修改应先形成待审核提案，由人工确认后再生效。检索得到切片，也不等于已证明切片进入了某次模型请求；相关文章与页面不会混淆这两个状态。

### 让报告更容易复现

报告以漏洞简介、漏洞描述、受影响 URL 和复现步骤为主要内容。复现材料优先展示 HTTP 请求包及关键响应证据，不把一串 curl 命令作为唯一交付。

请求中的令牌、Cookie、个人信息与业务数据应按需要脱敏；不能为了展示效果公开真实凭据。

### 让代理使用可以检查

代理模块不仅需要“填一个地址”，还需要区分节点是否可用、是否启用、由哪些任务使用，以及记录到的出口信息。

但“配置了代理”不能直接等同于“所有网络流量都被强制代理”。外部工具、自行创建连接的扩展与原生进程需要分别检查覆盖边界，目前不作全流量强制代理的承诺。

## 部署方向

交付包采用原生部署路线，不要求使用 Docker。Windows 双击入口会下载所需依赖、编译程序，并启动独立 PostgreSQL；首次安装需要联网。

| 项目 | 当前约定 |
| --- | --- |
| 应用入口 | 默认仅监听本机 `127.0.0.1:5173` |
| 独立数据库 | 默认仅监听本机 `127.0.0.1:5433` |
| 管理员密码 | 首次自行设置，不提供统一默认密码 |
| 端口冲突 | 停止并提示，不抢占其他服务 |
| 私有数据 | 不随源码、截图或文章发布 |

这只是部署方案介绍。本文没有安装入口，也没有已发布的预编译程序；源码通过审核后再另行说明获取和部署方式。旧环境迁移与全新安装需分开处理，不能直接覆盖业务数据库。

## 当前进度

截至 2026-10-15，交付记录中已有以下验证：

| 已完成的检查 | 说明 |
| --- | --- |
| 48 项安装器基础回归 | 检查启动器相关行为，不等于全业务测试 |
| 32 项真实服务断言 | 在本机独立空库验证初始化、认证与恢复等路径 |
| 前后端构建 | 完成前端静态构建与 Go 内嵌构建 |
| 8 组界面检查 | 检查导航、配置排版等界面；配置写入使用模拟接口 |

上述结果来自已有 Windows 环境，安装验证复用了经过校验的依赖缓存，不代表干净系统上的首次联网安装已经通过。

发布前还要补齐：

- 真实模型、工具、流量、知识库、代理、漏洞发现到报告的完整受控任务验收。
- 原业务数据迁移演练，以及完整权限隔离、依赖与敏感数据审查。
- 干净 Windows 环境与 Linux / macOS 的实际安装测试。
- 浏览器后退草稿保护和部分静态预取回退等已知界面边界的处理。

原生 Agent 使用运行账号的本机权限，不提供容器隔离。建议在专用、低权限的测试环境中运行，不直接向公网暴露控制台或数据库。
