# Windows 离线版安装与更新

适用范围：GitHub Release 中附带 `bin/yunkun.exe` 和 `runtime/pgsql-18.4/` 的 Windows x64 完整离线包。本手册不适用于仅下载仓库源码快照的安装方式。2026-10-16 更新包含 Agent 请求预算和旁路会话检查点修复；具体行为及验证边界见 [修复记录](agent-reliability-2026-10-16.md)。

## 新安装

1. 下载 Release 的完整 ZIP 和对应 SHA-256 值，核对文件哈希；不要使用 GitHub 自动生成的 Source code ZIP 代替离线包。
2. 解压到当前用户可写、路径较短的独立目录。检查 `bin/yunkun.exe`、`runtime/pgsql-18.4/bin/pg_ctl.exe`、`setup-and-start-offline.bat` 均存在。
3. 双击 `setup-and-start-offline.bat`。默认只监听本机 `127.0.0.1:5173`，私有数据库默认使用 `127.0.0.1:5433`。已有其他进程占用端口时启动器会报错，不会接管或结束它们。
4. 等待就绪提示，再打开 `http://127.0.0.1:5173/`。首次为账号 `yunkun` 自行设置控制台密码；包内没有统一默认密码。
5. 登录后配置自己的模型、工具和授权范围，并在受控环境中验证实际任务。离线仅指安装与本机启动不需下载依赖；外部模型或数据源是否可用取决于部署方配置。

启动器在包内新建 `.yunkun-local/`，其中包括私有数据库、配置、凭据、日志和运行状态。请保护这个目录，不能发送给第三方，也不能上传到公开仓库。

## 已有离线安装的更新

不要把新 ZIP 整包解压覆盖正在使用的旧目录，也不要把旧目录中的 `.yunkun-local/` 拷贝进公开交付包。先阅读新版本的变更记录和数据库兼容说明；这次更新没有计划更改数据库格式，但应用启动可能执行数据库迁移，应先备份再升级。

1. 确认正在运行的进程确实属于该离线安装，记录当前版本、端口、目录、配置和当前 ZIP 的 SHA-256。暂停正在执行的任务并等待结束。
2. 在旧目录双击 `stop-offline.bat`，输入 `STOP`。启动器只停止其已核对归属的控制台及私有数据库；如失败，不要强制结束未知 PID，先检查 `.yunkun-local/logs/` 和端口占用。
3. 确认私有 PostgreSQL 已停止后，将**整个旧安装目录**复制到仅本机管理员可访问的备份位置，包含 `.yunkun-local/`、`skills/`、自定义文件及原二进制。备份可能包含密钥和业务数据，不要上传到 GitHub。备份完成前不得继续。
4. 将新 ZIP 解压到**另一个全新目录**，核对文件哈希和目录完整性。将旧目录的 `.yunkun-local/` 及用户自行维护的 `skills/` 或其他明确需要保留的资源复制到新目录；不要用新包中的示例配置覆盖旧配置。确认旧目录无运行进程后再启新目录。
5. 双击新目录的 `setup-and-start-offline.bat`。启动器会复用 `.yunkun-local/installation.json` 中的数据库端口和凭据，不能在已有安装上改用另一个 `-DatabasePort`。若 5173、数据库端口被旧进程占用，先确认归属，不要通过删除数据目录来“修复”。
6. 核对 `/api/health` 已就绪，完成登录和一次受控的 Agent、工具调用及任务历史读取检查；再依次检查知识库、代理资源、HTTP 证据和报告。只看到登录页面并不代表 Agent 已验收。

若旧安装使用了外部数据库、改过目录或有额外脚本，本手册的目录迁移步骤不一定适用；应先在独立测试环境验证，再安排有备份的升级。

## 故障和回滚

- 启动失败或数据源不可用时，保留 `.yunkun-local/logs/`，检查私有 PostgreSQL、端口、配置和健康检查，不要删除或重新初始化数据库。
- 回滚前先停止新版本，并留存新版本运行后产生的数据和日志。新版本如已修改数据库结构，旧二进制可能无法直接读取；需用**升级前的整目录备份**恢复到单独目录，再确认端口空闲后启动旧版本。回滚会丢失备份之后产生的新数据，应先评估和留档。
- 不要复制新版本已迁移过的 `.yunkun-local/` 到旧版本目录。不要在生产数据上反复试错；必要时在备份副本上复现。

本包不更改系统防火墙或安装系统服务。Agent 执行本机工具仍继承启动账号权限；仅对取得授权的目标使用。
